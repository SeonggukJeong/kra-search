## 3. 해석
- 키워드 단독은 거의 모든 유형에서 의미 검색보다 낮다(전체 0.7946 대 0.9122). 낱말이 질의와 문서에 겹치는 abbrev(1.0000)·temporal(0.9850, 의미 0.9695보다 높음)·keyword(0.9553)에서만 대등하다.
- 가장 크게 뒤지는 유형은 kra-plain(0.2068 대 0.6202, Recall@20 0.4386)이다. 일상 표현 질의에는 문서와 겹치는 낱말이 거의 없어 키워드가 약하다. P003·P008 은 100위 안에도 못 든다. 이 간격을 의미 검색이 메운다.
- 의미 검색이 못 찾던 D012(22~23위 → 14위)·D028(64~85위 → 12위)은 키워드에서 순위가 올랐지만 둘 다 여전히 10위 밖이다. 결합(M2)에서 두 신호를 합치면 10위 안으로 들어올 여지가 있다. 이 기대는 M2 에서 확인한다.
- M2 기대: 키워드의 강점(고유명사·약칭·시점 낱말)과 의미의 강점(바꿔 말한 질의)이 다른 곳에 있어, 하이브리드가 두 단독 점수보다 높아야 한다.

비교 조건의 차이(숫자를 읽을 때 감안):
- 추출이 M0 와 다르다 — M1 은 HWP 캡션(KI-015)·HWPML 판별(KI-010)이 더해져 글자가 조금 늘었다. 의미 검색 열은 M0 추출로 잰 값이다(M2 에서 같은 추출로 다시 잰다).
- 평가 문서는 매니페스트 제목이 **문서 제목(3.0)과 파일명(2.5) 필드 둘 다**에 들어간다. 실제 PC 의 파일 이름은 제목과 다른 경우가 많아, 이 키워드 점수는 실제보다 유리하게 나온다.
- 문서 1,004건을 읽었다(M0 는 1,005건). 새로 추출이 실패한 문서는 P0833(138MB HWPX, 크기 상한 `TooLarge`) 1건이며, 어떤 질의의 정답에도 없어 점수에는 영향이 없다. 암호 문서 3건(P0126·P0404·P0702)은 M0 와 같다.
- 속도(이 PC): 색인 약 1.4초(문서 1,004건) · 검색 p50 0.1ms / p95 0.2ms.

## 4. 개발 PC 색인 속도

개발 PC(Mac, Apple Silicon), 릴리즈 빌드, `--home /tmp/kra-home`(임시 폴더, 측정 뒤 삭제). 명령은 CLAUDE.md "개발 명령"의 `kra-search index` / `search`.

| 항목 | 값 |
|---|---|
| 공개 평가 세트 문서 수 | 1,000개 — 내용을 읽은 것 996, 못 읽은 것 4 |
| 색인 시간(전체, 처음부터) | 6.8초(`time` 의 total), `/usr/bin/time` 재측정 4.7초 |
| 검색 시간(명령 전체, 사전 로드 포함) | 고령친화도시 0.05초 · 일자리 전담반 0.06초 · 렛츠런파크 0.06초 · 산림항공 0.05초 |
| 키워드 색인 크기 | 7.9MB |
| meta.db 크기 | 12MB |
| 색인 최대 메모리 — 공개 세트 1,000개 | 약 508MB(507,805,696바이트) |
| 색인 최대 메모리 — 500만 자 문서 1개(`big.txt`, 문단 36만 개) | 약 239MB(238,731,264바이트), 색인 2.1MB·meta.db 23MB, 2.1초 |
| 키워드 색인만(사전 포함, 500만 자·1,000블록, 무시된 시험 `big_document_indexes_by_block`) | 약 140MB(140,410,880바이트) |

해석
- 검색 지연 기준 p95 ≤ 150ms 는 상주 앱 기준이다. 명령줄 실행은 형태소 사전 로드 시간이 매번 더해진 값이다(그래도 0.05~0.06초).
- 큰 문서 하나의 최대 메모리 239MB 는 DEC-041 의 리뷰 실측(한 값으로 넣을 때 약 1.2GB)보다 크게 작고 기준 300MB 안이다. 앱 전체(사전 약 43MB 포함)이므로 키워드 색인만의 140MB 보다 크다.
- 공개 세트 1,000개의 최대 메모리 508MB 는 문서 수에 비례해 늘어나는 값이 아니라 색인 쓰기 버퍼·meta 쓰기·사전·워커 응답이 겹친 값으로 보이나, 원인은 쪼개 확인하지 않았다. 저사양 PC(RAM 8GB 이하)에서 색인 중 메모리 기준은 m1-diag 결과로 확인한다.
- 못 읽은 4개는 위 §3 의 암호 문서 3건(P0126·P0404·P0702)과 크기 상한을 넘은 P0833 으로 보이며(파일명만 색인), 실패 종류별 확인은 m1-diag 결과로 한다.
