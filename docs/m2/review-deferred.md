# M2 리뷰에서 미룬 작은 항목들 (KI-060)

M2 Task 리뷰(작업 기록부 `.superpowers/sdd/2026-10-15-m2-hybrid-search/deferred-minors.txt`, 줄 번호는 그 파일 앞 칸)와 M2 최종 리뷰
(`final-review.md` 의 m-1~m-13, 미룬 항목 분류표의 RECORD)에서 미룬 것 가운데 M2 최종 수정에서 고치지 않았고 다른 KI 에도 없는 것만 모았다.
해당 크레이트를 다음에 손볼 때 이 목록을 먼저 본다. 고치면 줄 끝에 `— 해결(커밋)` 을 붙이고 지우지 않는다.

이미 다른 곳에 있어 여기서 뺀 것: 옛 세대 벡터 파일이 상주 앱에서 쌓임(KI-054), 끊긴 첫 색인 뒤 "처음부터 색인 여부: 예"(KI-055),
진단의 20만 자 통계 건너뛰기(KI-058), Windows 에서 만든 XLSX 의 SHA(KI-059), 벡터 파일 하나만 못 읽어도 의미 검색 전체가 꺼짐(KI-053).
M2 최종 수정에서 해결: 나눔 비교가 구조적으로 같음(I-1 → DEC-069), "전년 대비" 등 견줌 낱말의 날짜 칩(I-2 → DEC-070; 동기·같은 기간·비해 꼴과 "비교적"·"대비책" 통째 낱말 규칙도 같은 DEC, 날짜 규칙은 M2 에서 동결),
연도 없는 날짜·달의 말이 미래(m-1 → INC-022), 벡터 파일 입출력 오류에 벡터를 지움(m-4·줄 89 의 일부 → INC-023),
키워드 기준선 이름(m-6), 보고서의 "가산 끔" 이 ✕ 상태가 아님(m-7), 보고서의 시간·"날짜 표현" 이름(m-8·줄 180),
KI-003 시험 빈틈(m-9), params.json 카드 상한과 제품 상수(m-10), 보고서의 "청크"(m-12). 이미 해소: 줄 76·78·124·131·187(최종 리뷰 분류표).

## query
- 지난겨울: 겨울의 마지막 날(02-28)에는 `end < today` 가 거짓이라 한 해 전 겨울을 돌려준다 — 동작은 논쟁거리이고 시험이 없다(줄 75).
- `title_years("2000 명 참석")` → [2000], `"IMG 2048"` → [2048] — 공백 뒤 4자리 숫자를 해로 읽는다. 제목 연도가 파일 날짜를 이기므로 드물게 가산이 틀린다(줄 77).
- `query::parse`·`title_years` 에 NFC 정규화가 없다 — 맥에서 만든 압축의 NFD 이름 "2025년 계획.hwp" 은 해를 못 읽고 NFD "올해" 는 칩이 없다. 키워드 토크나이저는 정규화한다(최종 리뷰 m-3). `DateTable::find` 머리에서 한 번 `nfc()`(바이트 위치는 정규화한 글 기준으로).

## index (+ extract·query: 제목 연도)
- 제목 연도의 출처에 오래된 메타데이터 제목이 섞인다 — DOCX·PPTX·XLSX·ODF·PDF 의 제목은 core.xml/메타가 먼저라 서식 찌꺼기("2019년 업무보고")가 흔하다. `date_title_conflict = 0` 이라 파일 이름에 해가 없는 문서는 1년 단위 칩마다 파일 날짜 가산을 잃고 "2019년" 에는 잘못 오른다. 여러 해 제목 "2024~2026년 중장기 계획" → [2024, 2026] 이라 2025 칩은 0. HWP(첫 머리글)는 해당 없음. 제목 연도는 본문 머리글에서 읽은 제목 + 파일 이름만 쓰는 안(최종 리뷰 m-2).
- `phrase_ids` 가 `MAX_QUERY_WORDS` 를 무시하고 파일 이름·2글자 필드를 건너뛴다, 블록을 넘는 구절·제목 일치 구절 시험 없음 — `phrase = 0` 인 동안은 잠들어 있다. 다시 조정에서 켜면 먼저 본다(줄 93).
- `meta`: `main_done`·`tail_done` 이 경로로 거르지 않아 고아 내용이 잠깐 섞여 셈, `check_finds_damaged_pages` 는 열기와 검사 중 어느 쪽이 잡았는지 모름, `vector_snapshot` 은 읽지 못한 길이·세대를 말없이 0 으로(kv 손상 시 조용한 0)(줄 120).

## vector
- `VecFile::create` 뒤 상위 폴더 fsync 없음, `read_from` 의 panic 이 문서에 없음, `check_header` 가 머리 읽기 입출력 오류를 `BadHeader`(손상)로 셈 — 열기 오류는 INC-023 으로 가렸지만 머리 읽기 중 오류는 여전히 다시 만들기, 부분 레코드 자르기·부분 뒤 `Short` 시험 없음(줄 89).

## app
- `vectors`: `vec_fp` 를 스냅샷 밖에서 읽음(좁은 경합, RF3), 세대+1 찌꺼기·머리는 맞고 짧은 파일의 app 시험 없음, `compact_if_needed` 의 `len as usize - live.len()` 은 `saturating_sub` 로(meta 가 파일보다 많이 알면 넘침), `model_hash` 의 수정 시각 0 대체가 특이한 파일 시스템에서 모델 바꿔치기를 가릴 수 있음(줄 125).
- `embedding`: `cards_empty` 가 실패를 두 번 셈, 청크 `from_full` 거절이 세어지지 않음. `main.rs`: `--model` 을 줘도 "찾지 못함" 안내가 기본 gguf 이름을 말함(줄 132 — 사용자에게 보이는 것은 마지막 하나).
- `embedding`: 모든 묶음·낱개 임베딩이 실패하면(메모리 부족의 `Decode` 등) 모든 단위가 `slot = None`(빈 것)으로 기록되고 다시 시도하지 않는다 — 지문이 바뀌어야 회복(시험 `failed_input_is_recorded_and_not_retried` 가 이 동작을 고정). 연속 N 번 실패면 단계를 멈추고 기록하지 않거나, 실패를 "빈 것"과 따로 적어 다음 실행에서 한 번 다시(최종 리뷰 m-5).
- `search`: 읽기 전용 저장소에서 모델 해시 캐시가 낡으면 검색마다 모델을 다시 해시, 모델이 없을 때 안내 하나 때문에 벡터를 모두 읽음, 상주 검색기에서 안내가 지워지지 않음, `Ok(v.len() != 1)` 을 말없이 키워드만으로, 시험 없음: 모델 없음 안내·검색 중 임베딩 실패·검색기의 `Unreadable`(줄 146 — 상주 검색기는 M3).
- `search::why_line` 이 경계 근처 절반 가산에도 "기간 안" 이라고 한다 — `date_boost < full` 이면 "기간 근처"(또는 M3 화면에서)(최종 리뷰 m-11).
- `eval --queries`: 여러 내용과 맞음·일부만 찾음 표시가 `run_user_queries` 에서 시험되지 않음, 검색기의 `Ok(v.len() != 1)` 키워드 대체를 평가 도중 검사가 못 잡음, 제품 경로에서 `UserQuery.answers` 를 쓰지 않음(줄 182).

## m0eval
- 날짜 표현 빼기 규칙의 첫 페이지 조건이 한쪽뿐 — `strip_relative`(기본 켬)를 끄는 쪽은 첫 페이지 적중을 잃어도 고를 수 있다. 합격 줄은 카드 상한을 정하기 전 256 으로, 고정 상한 실행의 빼기 표는 기본 상한으로 판정(줄 156 — 폐쇄망 뒤 다시 조정할 때 본다).

- `make_data_set.py --check` 가 매니페스트만 보고 `queries.tsv` 는 보지 않음(줄 51).
