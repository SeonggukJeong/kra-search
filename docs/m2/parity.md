# M2 일치 검사 (실험 = 제품, DEC-052 · DEC-059)

`kra-search --home target/eval-home eval --set eval/public --set eval/kra --set eval/data --dump target/app-ranks.json` 와 `m0eval --parity target/app-ranks.json` 의 결과. 매개변수는 제품 기본값(`HybridParams::default()` = `docs/m2/params.json`), 카드 상한 256, 데이터 뒷부분 켬.

## (i) 구조: 같은 벡터 → 같은 순위

m0eval 의 키워드 색인·날짜·제목 연도·문서 번호에 **제품이 저장한 카드·청크 벡터**(meta 의 살아 있는 슬롯)와 제품처럼 하나씩 임베딩한 검색어 벡터를 넣어 순위를 낸다.

| 항목 | 값 | 기준 |
|---|---|---|
| 비교한 질의 | 255/255 | 전부 |
| 상위 100개가 순서까지 같은 질의 | 255/255 | 100% |
| 판정 | **통과** | |

## (ii) 입력: 같은 글 → 거의 같은 벡터

카드·청크는 문서 id + 위치(문서 안 슬롯 순서 = 우선순위 순서의 위치)로 짝짓고, m0eval 벡터를 제품과 같은 양자화(`Record::from_full`, int8 512차원)에 통과시킨 뒤 **int8 코드끼리** 코사인을 잰다(역스케일은 코사인에 영향 없음). 검색어는 m0eval 의 하나씩 임베딩한 캐시 벡터와 제품식으로 지금 다시 임베딩한 벡터를 원본 차원(f32)으로 잰다. 글·렌더링(제목 머리·청크 경계·날짜 빼기)이 다르면 코사인이 훨씬 낮아진다.

| 대상 | 개수 | 최소 | 하위 1% | 중앙값 | 0.999 미만 |
|---|---|---|---|---|---|
| 카드 | 1058 | 0.999427 | 0.999509 | 0.999722 | 0 |
| 청크 | 22473 | 0.999164 | 0.999511 | 0.999717 | 0 |
| 검색어 | 255 | 1.000000 | 1.000000 | 1.000000 | 0 |

판정 **통과**

llama.cpp 의 임베딩은 같은 ubatch 에 함께 들어간 다른 입력에 따라 조금 달라진다(같은 글을 하나씩 vs 여러 개 묶어 넣으면 코사인 ≈0.9998; 스레드 수와는 무관하고, 묶음 구성이 같으면 비트까지 같다). m0eval 캐시는 빠진 항목만 그때그때 묶어 계산해 묶음 구성이 제품 색인과 다르므로, 각자 계산한 벡터로는 점수 차이가 1e-3 안팎 생기고 RRF 결합에서 아래 순위가 자주 뒤바뀐다. 그래서 순위 일치는 같은 벡터로만 판정하고(i), 벡터 자체는 코사인으로 확인한다(ii) — DEC-059. `docs/m2/eval-hybrid.md` 의 숫자는 8개씩 묶어 임베딩한 검색어 벡터로 계산했다(위 둘째 행이 그 방식의 앱 대비 차이, 첫째 행과의 차이가 묶음 잡음의 크기).
