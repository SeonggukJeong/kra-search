# UI/UX 결정 기록

> 구현 시 이 문서가 화면 동작의 기준이다. 목업(`mockups/`)과 이 문서가 다르면 **이 문서가 우선**한다.
> 결정을 바꿀 때는 이 문서를 먼저 고치고 날짜와 이유를 남긴다.

## 확정된 결정

### D1. 메인 검색창 레이아웃 = 적응형 (2026-10-12 확정)
- 목업: `mockups/search-layout.html` 의 **C안** (A·B는 C의 상태로 흡수됨)
- 처음 열면 검색줄 한 개만 있는 작은 창 (A 상태). 플레이스홀더: "무엇을 찾으세요? 예: 작년 예산 관련 공문"
- 결과가 나오면 **목록 + 미리보기 2분할**로 넓어짐 (B 상태). 사용자가 조절한 창 크기를 기억한다.
- 화면(작업 영역) 폭이 1000px 미만이면 A 상태 유지, 미리보기는 `Space`로 토글.
- 설정 "결과 미리보기 패널": 자동(화면 폭, 기본) / 항상 / Space로.
- 검색줄 아래 필터 칩: 📅 날짜 칩(검색어에서 인식, ✕로 해제), 형식, 기간, 🛡 개인정보.
- 결과 행: 형식 아이콘, 제목(공문 제목 우선, 없으면 파일명), 경로·수정일(공문이면 문서번호·시행일·수신), 일치 구절 하이라이트, 배지(`버전 N개 ▾`, `🛡 유형 개수`, `🔒`).
- 미리보기 패널: 제목, 경로, 수정일·형식·쪽수, 버전 목록, 일치한 구절(쪽/표 위치 표시, 개인정보 마스킹), 버튼 [열기] [폴더 열기] [경로 복사], 하단 **"왜 이 결과?"** 한 줄.
- 키보드: `↑↓` 이동 · `Enter` 열기 · `Ctrl+Enter` 폴더 열기 · `Space` 미리보기 · `Esc` 닫기 · `Tab` 대기 중인 새 결과 반영.

### D2. 단계적 결과 표시와 순서 변경 UX = "부드러운 이동 + 대기 배너" (2026-10-12 확정)
- 목업: `mockups/reorder-ux.html` 의 **C안**
- 결과는 단계적으로 표시: 파일명(즉시) → 키워드(입력 멈춤 150ms 후) → 의미 검색(임베딩 완료 후).
- **사용자가 목록을 아직 건드리지 않았을 때**: 새 결과를 자동 병합. 기존 항목은 200ms 미끄러지듯 이동, 새 항목은 위에서 살짝 내려오며 테두리가 한 번 빛남. 배지는 남기지 않음.
- **사용자가 방향키/마우스로 목록을 보기 시작한 뒤**: 목록을 절대 바꾸지 않는다. 상단에 배너 "↑ 의미 검색 결과 N개 더 · Tab으로 반영"만 표시.
- 선택(강조)된 항목은 어떤 경우에도 위치가 바뀌지 않으며, `Enter`는 항상 화면에 강조된 항목을 연다.
- 상단 진행 표시: `의미 검색 중…` → 완료 시 `✔ 검색 완료` 후 사라짐.
- Windows "애니메이션 효과 끄기"가 켜져 있으면 애니메이션 없이 즉시 반영 + 배너만.
- 화면 낭독기에는 aria-live로 "의미 검색 결과 N개 추가" 안내.

### D3. "왜 이 결과?" (2026-10-12 확정)
- 미리보기 패널 하단 한 줄. 예: `키워드 일치 3곳(제목 1) · 의미 유사도 높음 · 2025년 문서`

### D4. 요약/질의응답(2차)은 별도 창 (2026-10-12 확정)
- 검색창은 단순하게 유지. 2차에 미리보기 패널에 `요약` 버튼, 다중 선택 시 `이 문서들로 질문하기` 버튼만 추가.
- "문서 도우미"는 별도 Tauri 창. 검색창에서 선택한 문서(문서 ID + 청크 ID 목록)를 넘겨받아 시작.
- 1차 구현 범위: 다중 창 구조와 "문서/청크 ID 목록" 전달 계약까지만. 화면은 만들지 않는다.

### D5. 나머지 화면 ①~⑦ (2026-10-12 확정)
- 목업: `mockups/other-screens.html` (목업 그대로 구현)
- ① 첫 실행: 범위(모든 로컬 드라이브·대상 형식·제외 목록·[범위 변경…]), 발견 문서 수 + 단계별 예상 시간, PC 성능 감지 → 프로필(저사양/보통/고성능) 추천, 저사양이면 상주 모드 끄기 권장, [나중에] [색인 시작]. "데이터는 외부로 나가지 않습니다" 문구 필수.
- ② 트레이 메뉴 순서: 검색 열기(단축키 표시) / ─ / 색인 일시 정지 ▸(1시간·오늘) / 색인 현황(의미 %) / 개인정보 점검(개수) / 설정 / ─ / 종료. 아이콘: 색인 중 회전 점, 일시 정지 ⏸.
- ③ 단축키 충돌: 기본 `Ctrl+Space` 등록 실패 시 대화상자 → 대안 `Ctrl+Shift+Space`(기본 강조), `Alt+S`, [직접 지정…].
- ④ 색인 현황: 1단계/2단계 진행률, 형식별 문서 수, 읽지 못한 파일(🔒 DRM · 🔑 암호 · ⚠ 추출 실패/손상 · ⏱ 시간 초과/100MB 초과, 클릭 시 목록), EFS 상태, 색인 크기, 파일명 엔진(서비스) 상태, [일시 정지] [다시 색인…]. EFS 불가 시 ⚠ 경고 문구(목업 하단 문구 그대로).
- ⑤ 개인정보 점검: 위험도순 표(위험도·파일/경로·포함 항목 개수·수정일·[폴더 열기]), 유형 필터(전체/주민번호/외국인·여권·면허/계좌/휴대폰·이메일). **번호 값은 절대 표시하지 않음.** 위험도 = 유형 가중치(주민번호 > 외국인·여권·면허 > 계좌 > 휴대폰 > 이메일) × 개수.
- ⑥ 설정 탭: 일반 / 색인 범위 / 성능 / **모델(D6)** / 약어 사전 / 개인정보·보안 / 정보. 일반 탭 항목은 목업 그대로.
- ⑦ 접근성: 키보드 전용 사용, 포커스 테두리 상시, ARIA + aria-live, 고대비·125~200% 배율, 색+글자 병기, 애니메이션 끄기 설정 존중.

### D6. 설정 > 모델 탭 (2026-10-12 확정)
- 목업: `mockups/model-settings.html`
- 슬롯 2개: 🔍 검색용(임베딩, 1차) / 💬 요약·질의응답(언어 모델, 2차 — 1차에선 비활성 자리만).
- 기본 모델 EmbeddingGemma 2는 설치파일에 포함. 추가 모델은 로컬 GGUF 파일 선택(다운로드 없음).
- 추가 시 자동 검사: 불러오기 → 모델 프로필(내장 또는 고급 설정에서 수동) → 차원 → 예문 검사 → 이 PC 속도.
- 전환: 새 벡터 색인을 백그라운드에서 별도 생성, 완료 시 원자적 교체. 진행 중엔 기존 모델로 검색. 키워드 색인은 재사용. 이전 색인 보관 → [이전 모델로 되돌리기] / [이전 색인 삭제].
- 🔒 기관 정책으로 고정된 항목은 잠금 표시.
- (변경) 기존 ⑥의 "정보 탭: 모델 고정" 문구는 D6으로 대체됨.
