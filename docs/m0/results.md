## 설계에 반영할 발견(스펙 개정 후보)
1. **후보 수**: "후보 1,000개 고정" → `max(1,000, N × 2%)`.
2. **결합 점수**: 카드와 청크 단순 평균은 청크 단독보다 나쁨 → M2에서 가중치·최댓값 방식 비교.
3. **Windows 빌드**: llama.cpp DLL은 동적 CRT(/MD) + VC++ 런타임 앱 로컬 배포, 최적화 옵션 명시(스펙 §11 수정 필요).
4. **llama.cpp 패치**: 풀링 임베딩에서 logits 버퍼 미할당(최대 메모리 1.65GB → 0.65GB). llama.cpp 버전을 올릴 때 패치를 다시 맞춰야 함.
5. **rhwp 의존 방식**: cargo git 의존 대신 부분 복제 스크립트(`tools/fetch-rhwp.sh`) — rhwp 저장소가 8.6GB.
6. **추출 방식**: rhwp RAG 청커 대신 문서 모델 직접 순회(DEC-027). 추출 품질 기준에 "성공률"과 함께 **커버리지**를 둔다(스펙 §6·§15 추가 후보).
7. **고유명사·숫자 질의는 의미 검색만으로 못 찾음**: D012 "변화관리협의체 고위험 모니터링단"(개정안에 글자 그대로, 22~23위), D028 "손해배상 책임보험금 상향 금액"(운영계획 각주 "10억→20억", 64~85위 — 1위는 금액이 많은 전세사기 보도자료). 스펙의 키워드(BM25) 결합이 꼭 필요하다는 근거 — M2 하이브리드 평가에서 이 질의들을 회귀 기준으로 쓴다.
8. **일상 표현 질의가 가장 어렵다**: 규정 용어를 모르는 직원의 질의(kra-plain)는 nDCG 0.58~0.67(청크 점수)로 다른 유형보다 낮다. "일 미루고 대충 처리하는 것도 문제가 되나"(정답: 소극행정 유형 표)는 69~101위, "오래 안 쓴 계정에 남은 돈 돌려받기"(정답: 숨은 잔액 찾기)는 12~33위(1위는 금융권 휴면자산 환급 보도자료) — 질의에 문서 용어가 없어 키워드 검색도 못 돕는다. 실사용 피드백(스펙 §16)과 M2 평가에서 이 유형을 늘린다.
9. **실제 업무 문서에서 Q4 손실이 더 크다**: 공개 보도자료 질의에서는 Q8·Q4 차이가 없지만 마사회 질의에서는 Q8이 일관되게 앞선다(위 표). 질의 51개라 표본은 작지만 방향이 세 유형 모두 같다. 정부 전체 적극행정 보도자료(P0013 등)처럼 주제가 같은 방해 문서가 많을수록 차이가 커지는 것으로 보인다 — 실제 PC 에는 이런 공문이 훨씬 많다.
10. **출처별 섹션으로 나누면 다른 출처 문서에 밀리는 실패가 대부분 사라진다**(eval-dev.md §6, 사용자 제안 2026-10-13): 마사회 질의 72개 중 정답이 3위 안에 드는 질의가 한 목록 64개 → 마사회 섹션 72개(Q8). D028 85위 → 섹션 1위, D012 23위 → 2위, P013 70위 → 3위. **단 과대평가**: 평가의 마사회 섹션은 문서 8건뿐이라 섹션 안 순위가 쉽게 높다. 실제 PC 의 "우리 기관 문서"는 수천 건이므로 효과는 실사용·M2 에서 다시 잰다. 사용자 판단으로 **기타 아이디어로 보관**(스펙 §16 "기타 아이디어") — 실제 업무 검색은 대부분 내부 문서라 써 보면서 필요하면 꺼낸다.
