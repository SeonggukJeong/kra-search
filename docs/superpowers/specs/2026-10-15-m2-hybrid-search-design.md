# M2 설계: 의미 검색(문서 카드·본문 청크) + 하이브리드 검색 + 날짜 가산 + 평가

- 작성 2026-10-15. 상위 스펙: `2026-10-12-kra-search-design.md`(§6·§8·§13·§14). 이 문서는 M2 에서 새로 정한 것과 스펙을 구체화한 것만 적는다.
- 입력: `docs/m1/results.md` §5(폐쇄망 m1-diag-2 실측), 스펙 결정 #27, KI-001·003·017·041.
- 범위: 명령줄(`kra-search`)만. 화면(M3), 상주·유휴 감지·성능 프로필(M5), 공문 구조·약어·개인정보(M4)는 범위 밖.

## 1. 목표와 완료 기준

| 기준 | 측정 |
|---|---|
| 하이브리드 > 키워드 단독 | **검증용** 질의의 유형별 nDCG@10 평균(매크로) + 질의별 승·무·패 |
| 날짜 가산 켬 > 끔 | `date` 질의(전체·검증용) nDCG@10. 날짜 표현 없는 질의는 떨어지지 않을 것 |
| `temporal` 회귀 없음 | 날짜 표현을 검색어에서 빼는 규칙이 기존 `temporal` 질의를 떨어뜨리면 그 규칙은 쓰지 않는다 |
| 실험 = 제품 | 일치 검사 통과(§6.5) |
| 검색 지연 | 의미 포함 p95 ≤ 500ms, 본문 청크 50만(합성 벡터 벤치 + 폐쇄망 실측) |
| 폐쇄망 확인 | 실제 업무 문서로 색인·`eval --queries` 실행, 보고서 반출(§7) |

"감으로 판단하는 평가가 없을 것"이 설계 원칙이다. 판단이 필요한 모든 값은 숫자 규칙으로 정하고(§6.4), 평가 세트가 원리상 재지 못하는 것(실제 업무 문서 경쟁, 실제 수정일 잡음, 실제 PC 속도)은 폐쇄망 확인(§7)으로 잰다.

## 2. 구조

| 크레이트 | M2 에서 추가 | 성격 |
|---|---|---|
| `query` (신규) | 날짜 표현 해석, 검색어 유형 분류. `parse(검색어, 기준 시점) → ParsedQuery` | 순수 함수. 기준 시점은 바깥에서 주입 |
| `index::hybrid` (신규 모듈) | **검색 코어**: 키워드 결과 + 벡터 스캔(카드·청크) + 결합 + 보정 → 문서 순위와 경로별 기여 | 매개변수 `HybridParams`. **실험(m0eval)과 제품(app)이 같은 함수를 부른다** |
| `vector` | 디스크 저장소(고정 길이 레코드·세대 파일·꼬리 자르기·압축). 스캔은 기존 `FlatIndex` | 의존성 없음 유지(KI-008) |
| `embed` | 대기열 순서 계산, 임베딩 trait(`Embed`: 실제 엔진 / 시험용 가짜), KI-001(`cut_to`), KI-003(로그 무음) | |
| `platform` | 성능 코어 수(진단의 `EfficiencyClass` 판별을 옮김, 그 외 OS 는 물리 코어 수) | |
| `app` | `index` 에 카드·본문 단계, `search` 를 하이브리드로, `eval` 명령, `--now`(숨김) | |
| `m0eval` | 벡터 캐시로 `HybridParams` 훑기, 보고서 `docs/m2/eval-hybrid.md` | 결합은 `index::hybrid` 를 그대로 부른다 |

흐름
- 색인: 훑기·추출 → 키워드 반영(M1) → 카드 → 본문 ①→②→③(§3.3). 묶음마다 벡터 파일 → meta.db 순으로 기록.
- 검색: `query::parse` → 키워드 검색 + 검색어 임베딩 → 카드 전체 스캔 · 청크 이진 선별→int8 재계산 → `index::hybrid` → 결과(경로별 순위·점수 포함, UI D3 "왜 이 결과?"의 재료).
- 명령줄 `search` 는 실행마다 모델을 불러온다(상주·미리 불러오기는 M3·M5). `eval` 은 한 번만 불러온다.

## 3. 색인

### 3.1 meta.db 스키마 v2
- v1 → v2 **이전(migration)**: 테이블을 더할 뿐 다시 추출하지 않는다(실제 PC 에서 수 시간).
- 추가: 내용별 카드 슬롯·청크 수·진행, 청크별 슬롯(내용 id, 순번, 슬롯), kv(벡터 파일 세대·길이, 임베딩 지문, ③ 켜기/끄기).
- 청크 텍스트는 저장하지 않는다 — 문서 JSON·토크나이저·청크 설정으로 언제나 같게 다시 만든다. 구절 미리보기(M3)에서 다시 판단.

### 3.2 벡터 파일
- 위치 `data/vectors/<임베딩 지문>/cards.<세대>.vec`, `chunks.<세대>.vec`. 머리(형식 표시·버전·차원) + 고정 길이 레코드(int8 512 + 배율 f32 + 이진 768비트 ≈ 612바이트). 슬롯 = 레코드 순번.
- **임베딩 지문 = 모델 파일 해시 + 모델 프로필 + 카드 상한 + 청크 설정.** 하나라도 바뀌면 벡터만 다시 만든다(키워드·meta 유지). 모델 해시는 (크기, 수정 시각)이 같으면 kv 에 둔 값을 쓴다.
- **삭제 기준은 meta**: meta 가 가리키지 않는 슬롯은 죽은 것. 실행 끝에 죽은 비율 > 30% 이면 압축 — 새 세대 파일에 쓰고 meta 의 현재 세대를 바꾼 뒤, 옛 세대는 다음 실행에서 지운다(Windows 에서 다른 프로세스가 연 파일은 바꿔치기할 수 없음).
- 쓰기 순서: 레코드 추가 → fsync → meta 트랜잭션(슬롯 행 + 파일 길이). 열 때 파일이 길면 꼬리를 자르고, 짧거나 머리가 다르면 벡터만 다시 만든다.
- `search` 는 meta 에 기록된 길이까지만 읽는다 → `index` 가 쓰는 중에도 일관된 상태.
- 벡터는 키워드 색인처럼 `data\` EFS(M5)로 보호한다(별도 암호화 없음).

### 3.3 대기열 순서 (실행 때 SQL 로 계산, 저장하지 않음)
1. **카드**: 문서 형식(hwp·hwpx·pdf·docx·pptx·odt·odp) 먼저, 그 안에서 최근 수정 먼저(결정 #27). 형식은 그 내용의 첫 경로 확장자, 수정일은 경로들 중 최신.
2. **본문 ①**: 문서 형식 본문 전체. 50청크 조각 단위 공정 스케줄링 — 모든 문서의 1번째 조각을 최신순으로, 그다음 2번째 조각… 문서 안에서는 소제목을 담은 청크가 먼저(스펙 §6.6).
3. **본문 ②**: 데이터 형식(txt·csv·xlsx·ods) 문서당 앞 20청크.
4. **본문 ③**: 데이터 형식의 나머지, 스펙 상한(표 200 · txt 2,000)까지. **설정으로 끌 수 있고 기본 켬**(저사양 프로필 기본 끔은 M5).
- 진행률 분모는 ①+②(③은 별도 줄). 본문 단계 시작 때 모든 문서의 청크 수를 먼저 센다(토큰화만).
- 내용 해시 단위: 이름 바꾸기·옮기기는 다시 임베딩하지 않는다. 재시도(`retry_content`)로 같은 id 의 문서가 바뀌면 그 내용의 벡터 행을 지우고 다시 대기열에 넣는다. `reset_store` 는 벡터 폴더도 지운다.

### 3.4 실행
- `index` 가 키워드 → 카드 → ①②③ 을 차례로 돈다. **스펙 §6.2 의 "유휴 시"는 M5** 에서 붙인다(M2 는 명령 안에서 끝까지).
- 64개마다 커밋 → Ctrl+C 뒤 이어서 한다.
- 스레드 기본 **min(4, 성능 코어 수)**, `--threads` 로 변경(KI-017, results.md §5.2: Q8 4스레드가 최고의 97%, 논리 스레드 전부는 7~12배 느림).
- 진행 표시·`status`: `빠른 의미 검색 n/N · 정밀 의미 검색 n/N · 데이터 파일 뒷부분 n/N`.
- 제목이 없으면 카드·청크 머리를 파일 이름으로(`title: {제목|파일명}`, 스펙 §6.6).
- 모델 기본 위치는 실행 파일 옆 `models\`, `--model` 로 변경.
- 미룸: 낮은 CPU 우선순위·EcoQoS(M5), 벡터 메모리 매핑(M3 — 명령줄은 검색 때 메모리로 읽는다, 청크 50만 ≈ 300MB).

### 3.5 오류 처리
| 상황 | 동작 |
|---|---|
| 모델 없음·불러오기 실패 | 키워드만 색인·검색, 한 줄 안내, 다음 `index` 에서 다시 시도 |
| 입력 하나 임베딩 실패 | 그 단위만 "없음"으로 기록하고 계속 |
| 벡터 파일 손상·길이 부족·지문 다름 | 벡터만 다시 만든다 |
| 벡터 일부만 있음 | 있는 것으로 결합(청크 없으면 카드로 대신) |

## 4. 검색

### 4.1 검색어 해석 (`query`)
- **날짜 표현은 데이터 표**(내장)로 둔다. 형식은 기관 사전 TSV 와 같게 하고, 바깥 파일을 **덧붙여 불러올 수 있게** 만든다(화면·정책 파일 연결은 M5). 표의 모든 줄을 단위 테스트한다.
- 인식 범위(한자어·구어·약식 포함):

| 단위 | 예 |
|---|---|
| 해 | 올해·금년·금년도·당해(연도)·작년·지난해·전년(도)·객년·재작년·지지난해·2025년(도)·25년·'25 |
| 반기·시기 | 상반기·하반기·전반기·후반기·연초·연말·연중·연말연시·작년 말·올 초 |
| 분기 | 3분기·3/4분기·3사분기·삼사분기·3Q·이번 분기·지난 분기·전분기 |
| 달 | 이번 달·이달·금월·당월·지난달·저번 달·전월·전달·지지난달·9월·9월 초/중순/말·월초·월말·2025년 9월·25.9월·2025.9 |
| 주 | 이번 주·금주·지난주·저번 주·전주·지지난주 |
| 날 | 오늘·금일·당일·어제·어저께·전일·그제·그저께·엊그제·9월 15일·'25.5.30. |
| 계절 | 봄·여름·가을·겨울·올봄·작년 여름·지난겨울(겨울은 해를 넘김) |
| 막연한 기간 | 최근·요즘·요새·근래·얼마 전·몇 달 전·몇 년 전·최근 3개월·지난 6개월·2년 전 |

- 규칙: 결과에 표현의 **종류(상대/절대)와 정확/막연**을 함께 돌려준다. 막연한 표현은 기간을 넓게, 가산을 약하게. **미래 표현(내년·명년·익년·차년도·다음 달)은 칩으로 만들지 않고 검색어에 남긴다**(올해 쓴 "내년 계획"). 연도 없는 달은 기준 시점에서 가장 가까운 지난 그 달. 띄어쓰기 변형은 정규화한다. 회계연도 = 역년.
- **날짜 표현을 검색어에서 뺄지는 종류별 매개변수**로 두고 평가로 정한다(스펙 §8.1 은 "뺀다" — 본문 내용인 "올해 3분기까지 수출 실적" 같은 질의에서 키워드를 잃는 위험을 `temporal` 질의로 잰다).
- 업무 고유 시간 표현(경마 "N주차·회차·시즌")은 넣지 않는다 — 실사용 피드백으로 표에 더한다(스펙 §16 기타 아이디어).
- 검색어 유형: 짧은 명사(2~3글자)·문서번호 꼴·파일명 꼴 → 키워드형, 문장 → 의미형. 사람 이름 인식(NER)은 2차.

### 4.2 경로와 결합 (`index::hybrid`, 값은 모두 `HybridParams` — §6 에서 정함)
- 키워드: 상위 200. 필드 가중치·bigram 가중치(DEC-038 잠정값)도 매개변수.
- 카드: 전체 int8 스캔 상위 200. 청크: 768비트 해밍 후보 max(1,000, 청크 수 × 2%) → int8 재계산 → 상위 200청크 → 문서로 묶음.
- 의미 점수 결합 후보: ⓐ 최고 청크(없으면 카드) ⓑ max(카드, 청크) ⓒ 카드·청크를 각각 RRF 목록으로 ⓓ 카드만(비교 기준).
- 유사도 하한 미만 의미 결과는 결합에서 뺀다.
- 가중 RRF: `Σ w_경로(검색어 유형) / (k + 순위)`.
- 보정: 날짜 칩 기간 안 문서 가산(정확/막연 세기 따로, 경계 근처 절반), 최근 문서 약한 가산, 정확 구절 일치 가산.
- 결과마다 경로별 순위·점수를 함께 돌려준다.
- 부분 상태: 벡터가 일부만 있어도 있는 것으로 결합, 모델이 없으면 키워드만.
- 지연 예산: 검색어 임베딩 Q8 p95 62ms + 청크 50만 스캔 21ms(폐쇄망 실측) + 결합 → 500ms 안.

## 5. 평가 세트 보강
- 매니페스트에 `date`(문서 날짜) 추가: 공개 문서 = korea.kr 게시일(개발 PC 에서 한 번 받는다), 마사회 문서 = 갑지 시행일.
- 마사회 문서 추가: K0009·K0010 = 2026년 경마시행계획(안) 요약·본문(경마기획부-1736, 2025-12-21), K0011 = 2025년 직원 역량강화 프로젝트 미국 출장 계획(안)(경마기획부-1432, 2025-10-25). 갑지 PDF 는 M4(공문 구조)에서 함께 넣는다(지금 넣으면 기존 질의 정답을 전부 다시 판정해야 함). 새 문서용 일반 질의 몇 개.
- **`date` 질의 30개**: 기준일 2026-10-15. 상대·절대·막연 표현과 한자어·구어를 섞는다. "작년 경마시행계획"(제목은 2026년, 작성은 작년) 같은 함정을 넣는다.
- **데이터 형식 방해 문서** 100~200개(공공데이터포털 공공누리 CSV·XLSX·TXT, 저장소에 넣지 않고 SHA-256 으로 다시 받음) + 정답이 **앞 20청크 뒤**에 있는 질의 5~10개 — ③ 의 이득과 잡음을 숫자로 잰다.
- 새 질의는 유형별 몇 개를 사용자가 검토한다(M0 과 같은 방식).
- 마사회 문서 추가(주제가 겹치는 계획서·규정)는 사용자가 시간 날 때 — M2 일정에 넣지 않는다.

## 6. 평가

### 6.1 조정용·검증용
- `qid` 해시로 유형별 60:40. 파일을 고치지 않아도 항상 같게 나뉜다. 매개변수는 조정용으로만 고르고 합격은 검증용으로 판정한다.

### 6.2 m0eval 실험
- 벡터는 항목별 캐시(DEC-032), 결합은 `index::hybrid`. 키워드 색인은 메모리.
- 훑는 값: RRF k · 경로 가중치(검색어 유형별) · 키워드 필드·bigram 가중치 · 의미 점수 결합 ⓐ~ⓓ · 유사도 하한 · 날짜 가산 세기(정확/막연) · 날짜 표현 빼기(종류별) · 최근·구절 가산 · 카드 128/256 · ③ 켬/끔.
- 방법: 좌표 하강(한 번에 하나씩, 수렴할 때까지). 목표 = 조정용 **유형별 nDCG@10 평균(매크로)** — 공개 질의가 많아 마사회 질의가 묻히지 않게.

### 6.3 보고서 `docs/m2/eval-hybrid.md` (자동 생성)
- 유형별 표: 키워드 / 카드 / 청크 / 하이브리드(조정용·검증용).
- 분해 표: 날짜 가산·하한·③·날짜 빼기 규칙 각각 켬/끔.
- 질의별 승·무·패(하이브리드 vs 키워드, 가산 켬 vs 끔).
- `date` 질의별 순위, 검색어 유형 분류 정확도(질의 `type` 열 기준: keyword·abbrev → 키워드형, 그 밖 → 의미형).
- 정답 문서 카드가 128토큰을 넘는 질의만 모은 점수와 개수(결정 #27 판정용).
- 일치 검사 결과와 실제 차이.

### 6.4 결정 규칙 (숫자로만)
- 매개변수: 조정용 매크로 nDCG@10 최대. 차이 0.005 이내면 더 단순한 쪽(기본값).
- 카드 128: 결정 #27 규칙 그대로(전체 −0.3%p 이상 또는 마사회 유형 −1%p 이상이면 256, 잘리는 카드 25% 미만이면 판단 불가 → 256).
- 날짜 빼기 규칙: 해당 종류의 규칙이 `temporal` 조정용 nDCG 를 떨어뜨리면 그 종류는 빼지 않는다.
- ③: 데이터 질의 이득과 비데이터 질의 손실을 함께 보고, 비데이터 매크로가 −0.3%p 이상 떨어지면 기본 끔으로 바꾸는 안을 사용자에게 올린다.

### 6.5 일치 검사 (실험 = 제품)
- 구조: 같은 벡터를 넣으면 m0eval 경로와 앱 코어가 같은 순위를 낸다 — 단위 테스트.
- 실제 경로: `kra-search eval --set eval/public --set eval/kra --now 2026-10-15` 는 평가 문서를 `{매니페스트 제목}.{확장자}` 이름으로 임시 폴더에 복사하고 **파일 수정일을 매니페스트 날짜로 설정**한 뒤 제품 그대로 색인·임베딩·검색한다(평가용 우회 없음). m0eval 과 전체 nDCG@10 차이 ≤ 0.002, 상위 10개 문서 목록이 순서까지 같은 질의 ≥ 98%. 허용 오차는 llama.cpp 스레드·묶음에 따른 부동소수점 차이 때문이며 실제 차이를 보고서에 적는다.
- 평가 색인 폴더는 재사용한다(바뀐 것만 다시 임베딩).

### 6.6 성능
- 청크 50만 합성 벡터 검색 지연 p95(`--ignored` 시험). 카드 처리량은 기존 진단 벤치.

## 7. 폐쇄망 확인 (M2 완료 조건)
- 릴리즈 워크플로에 `kra-search` 명령줄 묶음 추가(모델·pdfium·ggml DLL, SHA-256, 네트워크 0 검사).
- 안내서: 사용자가 업무 폴더를 `index` 하고, 직접 쓴 질의 20~30개(`질의<TAB>정답 파일명`, 날짜 표현 질의 포함)로 `kra-search eval --queries <tsv>` 를 돌린다.
- 보고서: nDCG@10·Recall@20(전체, 그리고 `query::parse` 가 날짜 표현을 찾은 질의와 못 찾은 질의로 나눠서 — TSV 에 유형 열이 없으므로), 날짜 가산 켬/끔 비교, 실패 질의 **번호**, 단계별 소요 시간, 청크 수, 검색 지연 p50·p95(검색어 임베딩 포함). **질의 원문·경로·파일명은 남기지 않는다**(INC-010 원칙).
- 태그 전 점검(INC-020): 이 결과로 정할 것(매개변수 재조정 여부, 날짜 가산이 실제 수정일에서도 이득인지, 실제 색인 시간)에 필요한 숫자가 보고서에 다 있는지 확인한다.
- 결과가 개발 PC 와 크게 다르면 그 데이터로 매개변수를 다시 정한다.

## 8. 테스트
- CI: 임베딩 trait 의 **가짜 임베더**(텍스트 해시 → 결정적 벡터)로 파이프라인 전체를 빠르게. 더해 **실제 모델로 작은 문서 묶음 색인 → 검색** 시험 하나(DEC-018 의 모델 캐시).
- 단위: 날짜 표 전체(기준 시점 고정, 연말·연초·윤년·겨울 해 넘김·미래 표현), 검색어 유형, 결합 코어, 대기열 순서, 지문, 벡터 저장소(꼬리 자르기·세대 교체·압축), 일치(같은 벡터 → 같은 순위).
- 통합: 색인 → 검색, 이름 바꾸기 시 다시 임베딩 안 함, 재시도로 문서가 바뀌면 벡터 무효화, 벡터 손상 → 벡터만 다시, 벡터 쓰기와 meta 기록 사이 중단(시험용 고장 주입 지점), 모델 없음 → 키워드만.
- Windows CI: 다른 프로세스가 벡터 파일을 연 채로 압축·세대 교체.
