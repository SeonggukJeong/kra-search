# KRA 문서검색 (kra-search) 설계 스펙

- 작성일: 2026-10-12
- 상태: 사용자 검토 대기
- 관련 문서: [UI/UX 결정 기록](../../design/ui-decisions.md) · [목업](../../design/mockups/)

## 1. 목적

대한민국 공공기관 직원이 **자기 PC 안의 업무 문서를 내용과 의미로 찾는** Windows용 로컬 검색 프로그램을 만든다. Google AI Edge Foresight처럼 모든 처리를 PC 안에서 하고, 공공기관 환경(HWP 중심, 망분리, 저사양 PC, 개인정보·보안 요구)에 맞춘다.

**핵심 가치**: "파일 이름은 모르지만 내용은 대충 기억나는" 문서를 1초 안에 찾는다.

**우선순위**: 모든 처리가 로컬이므로 **검색 품질 · 성능 · 속도를 최우선**으로 한다.

### 1.1 Everything과의 관계
| 상황 | 더 나은 도구 |
|---|---|
| 파일 이름을 알고 위치만 모를 때 | Everything과 동등 수준을 목표로 함 (M6 파일명 엔진) |
| 내용·의미로 찾을 때 (HWP/PDF/Office 본문, 약어, 공문 필터, 버전 정리, 개인정보 점검) | kra-search |

## 2. 사용자 · 환경 가정

**사용자가 정한 것**
- Windows PC, 무설치 실행 또는 단일 설치파일.
- 저사양 PC가 많음(일부 RAM 16GB PC 존재). 성능을 위해 Rust.
- HWP가 가장 많이 쓰이는 형식.
- 임베딩 모델: EmbeddingGemma 2.
- 공유 드라이브·USB 사용이 제한적 → **로컬 디스크가 핵심**.
- 문서중앙화 문서는 로컬에서 접근 불가 → 보류.
- Fasoo DRM은 대외용 위주로 일부 파일에만 적용.
- 관리자 권한 확보는 어렵지 않음. 대상 기관(한국마사회)은 Windows Enterprise 사용.
- 다른 공공기관과 공유할 가능성 있음 → 기관별 설정·라이선스 고려.
- 개발 PC는 macOS, 테스트는 사내 폐쇄망 Windows PC.

**설계상 가정**
- 망분리 환경: 실행 중 **외부 네트워크 호출 0**. 모델 등 모든 리소스 내장.
- 저사양 기준 PC: 2코어/4스레드(i3·셀러론 7세대급), RAM 4GB, SATA SSD, Windows 10. GPU 없음 → CPU 추론.
- 한 PC에 사용자 여러 명 가능 → 내용 색인은 사용자별.

## 3. 범위

### 3.1 1차 범위
1. 문서 내용 검색: **키워드(BM25) + 의미(임베딩) 하이브리드**.
2. 지원 형식(내용 추출): HWP, HWPX, PDF, DOCX, XLSX, PPTX, **ODT/ODS/ODP**, TXT/CSV.
   - 배포용 HWP 복호화 지원. 암호 문서·DRM·추출 실패 파일은 파일명·메타데이터만 색인.
3. 파일명 검색: 색인 대상 문서 + (설치판) **로컬 NTFS 전체 파일명**(MFT/USN 기반 서비스).
4. 공공기관 특화: 공문서 구조 인식, 약어·동의어 사전, 파일 버전 묶기, 개인정보 탐지·점검.
5. 상주형(트레이 + 전역 단축키) 기본, 설정에서 끌 수 있음.
6. 모델 관리: 기본 EmbeddingGemma 2 내장, 다른 GGUF 임베딩 모델로 교체 가능.
7. 배포: MSI(기본, 서비스 포함) + 무설치 zip(기능 축소).
8. 진단·평가 도구: `--diagnose`, `--eval`.

### 3.2 1차 비범위 (로드맵 §14)
LLM 요약·질의응답, 붙임 파일 연결, 네트워크 경로, 이미지·스캔 PDF 검색, 이름·주소 개인정보 탐지, 재순위 모델, 옛 Office 형식, 한셀/한쇼, 문서중앙화·Fasoo SDK 연동, GPU 가속.

## 5. 아키텍처

### 5.1 프로세스 구성
```
[kra-search-svc]  Windows 서비스, SYSTEM, 설치판만
   MFT 열거 + USN 저널 구독 → 파일명 색인(메모리) · 변경 이벤트 발행
   ↑↓ 로컬 named pipe (대화형 로그온 사용자만 접근 허용 ACL)
[kra-search.exe]  사용자 권한, 상주
   트레이 · 전역 단축키 · 작업 대기열 · 검색 서비스(tantivy/벡터/메타)
   WebView2 창: 열 때 생성, 닫은 뒤 10분 숨김 유지 후 해제
   임베딩 모델: 검색 시 로드, 5분 미사용 시 해제
   ↑↓ 로컬 파이프
[kra-search.exe --worker]  사용자 권한, 색인할 때만
   추출 → 개인정보 → 청크 → 임베딩, EcoQoS/백그라운드 모드, 파일당 제한 시간(기본 30초)
```
- 배포 바이너리는 앱 1개(+서비스 1개). 워커는 같은 exe를 옵션으로 실행.
- **문서 본문은 SYSTEM 권한으로 읽지 않는다.** 내용 색인은 사용자 권한 워커만 수행 → 파일 ACL이 자연스럽게 지켜짐.
- 서비스가 반환하는 파일명 결과는 표시 직전에 요청 사용자 권한으로 접근 가능 여부(AccessCheck)를 확인한 것만 노출.
- 서비스가 없을 때(무설치판·설치 차단): 지정 폴더 `ReadDirectoryChangesW` 감시 + 시작 시 mtime/크기 비교 스캔.

### 5.2 Rust 워크스페이스 모듈
| 크레이트 | 책임 | 의존 |
|---|---|---|
| `extract` | 파일 → `Document{title, blocks[], gongmun?, flags}`. 형식별 추출, 배포용 HWP 복호화, DRM/암호 감지 | 없음(순수) |
| `gongmun` | 블록에서 공문 메타(제목·문서번호·시행일·수신·발신·붙임 목록) 추출 | extract 타입 |
| `pii` | 식별번호 탐지(검증 숫자 포함), 자리표시자 치환, HMAC 생성 | 없음 |
| `embed` | llama.cpp 래핑, 모델 프로필, 청크 분할, 접두어, MRL 축소·양자화 | llama.cpp |
| `index` | tantivy 스키마, 벡터 저장소, SQLCipher, 하이브리드 검색, 버전 묶기 | embed 타입 |
| `query` | 검색어 해석(날짜 표현, 번호 형식, 약어 확장) | lexicon |
| `lexicon` | 약어·동의어 사전(내장 + 기관 TSV) | 없음 |
| `crawler` | 스캔·감시·대기열·우선순위 | platform |
| `platform` | Windows 전용: USN/MFT, EFS, DPAPI, 서비스, 단축키, EcoQoS, 유휴 감지. **macOS용 스텁 제공** | windows-rs |
| `app` | Tauri 셸, 트레이, 창 관리, IPC, 설정, 진단·평가 명령 | 전부 |
| `svc` | 파일명 엔진 서비스 | platform |

각 크레이트는 다른 크레이트 내부를 몰라도 단독 테스트 가능해야 한다. `platform`을 제외한 모든 크레이트는 macOS에서 빌드·테스트된다.

### 5.3 데이터 위치
`%LOCALAPPDATA%\KraSearch\` (사용자별)
- `index\tantivy\` — 키워드 색인
- `index\vectors\<모델지문>\` — 벡터(int8, 이진), 삭제 표시 비트맵
- `index\meta.db` — SQLCipher (파일·내용·청크 원문·상태·공문 메타·개인정보 개수·HMAC)
- `keys\` — DPAPI로 보호된 SQLCipher 키·HMAC 키
- `logs\`
- `index\` 폴더에 **EFS 적용**(가능한 경우). 불가 시 경고 후 계속(§7).
- 무설치판도 같은 위치를 사용(exe 옆에 쓰지 않음 — 권한·EFS 일관성).

## 6. 색인 파이프라인

### 6.1 흐름
```
변경 감지 → 작업 대기열(meta.db, 최근 수정 우선) → 워커: 추출 → 공문 인식 → 개인정보 → 청크 → (2단계) 임베딩 → 저장
```

### 6.2 2단계 색인
- **1단계(빠름)**: 추출 + 파일명/키워드 색인. 완료 즉시 키워드 검색 가능.
- **2단계(느림)**: 임베딩. PC 유휴 시(기본: 입력 없음 2분) 진행.

### 6.3 범위 · 제외
- 설치판 기본: **모든 로컬 NTFS 드라이브**의 대상 확장자.
- 무설치판 기본: 문서·바탕화면·다운로드 + 사용자 추가 폴더.
- 기본 제외: `Windows`, `Program Files*`, `AppData`, `$Recycle.Bin`, 임시 폴더, 한글 자동저장/백업(`.asv`, `.bak`), Office 임시(`~$*`). 사용자 편집 가능.

### 6.4 중복 제거
- 파일 내용 해시(xxh3-128) 기준으로 추출·임베딩은 한 번, 경로는 여러 개 연결.

### 6.5 추출
- 출력: `Document { title, blocks: [Block{kind: Heading|Paragraph|TableRow|Cell|Note, text, loc: 쪽/구역/표}], gongmun: Option<GongmunMeta>, flags: {drm, encrypted, distribution, truncated} }`.
- HWP: 배포용 문서 복호화. 암호 문서는 감지만.
- DRM: Fasoo 등 알려진 헤더 시그니처로 감지 → 🔒. **복호화 플러그인 인터페이스**(`trait Decryptor`)만 정의, 구현 없음.
- 파일 크기 100MB 초과: 내용 추출 생략.
- TXT/CSV: UTF-8/CP949 자동 판별.

### 6.6 청크 분할
- 구조 기반: 제목·문단 경계 존중. 표는 행을 `열이름: 값` 형태로 직렬화하되 **여러 행을 목표 크기까지 묶고, 청크마다 표 머리글을 반복**한다(행마다 청크를 만들지 않음).
- 목표 크기 300~500 토큰(M0/M2 벤치마크로 확정).
- 임베딩 입력 형식은 모델 프로필이 정의. EmbeddingGemma 2: 문서 `title: {공문제목|파일명} | text: {청크}`, 검색어 `task: search result | query: {검색어}`.
- **문서당 임베딩 청크 상한** (상한 초과분은 키워드 색인만):
  - 본문 문서(HWP/HWPX/PDF/DOCX/PPTX/ODT/ODP/TXT): 안전장치 **2,000청크**(약 700~1,000쪽). 사실상 상한 없음.
  - 표 데이터(XLSX/ODS/CSV): **200청크**.
- 추정: A4 보고서 1쪽 ≈ 한글 1,000~1,500자 ≈ 600~800토큰 ≈ 2청크. **M0에서 실제 HWP로 쪽당 토큰 수를 측정해 확정.**
- **공정 스케줄링**: 큰 문서는 50청크 단위 조각으로 나눠 여러 문서를 번갈아 처리(라운드 로빈). 짧은 문서가 먼저 완료되고, 큰 문서는 점진적으로 완성된다.
- 큰 문서는 **목차·소제목이 포함된 청크를 먼저** 임베딩해 문서의 큰 줄기가 먼저 검색되게 한다.

### 6.7 임베딩
- llama.cpp 배치 추론.
- 768차원 → MRL 256차원(벤치마크로 확정) → 재정규화 → int8 스칼라 양자화 + 부호 비트(이진) 저장.
- 양자화 수준(Q8/Q4)은 품질 우선: 속도 기준 충족 시 Q8.

### 6.8 저장 · 일관성
- meta.db가 기준. tantivy·벡터는 배치 커밋 후 커밋 번호를 meta.db에 기록. 재시작 시 커밋 번호로 정합성 복구.
- 벡터 파일은 추가 전용 + 삭제 표시. 삭제 비율이 높아지면 유휴 시 압축.

### 6.9 실패 처리
- 시간 초과, 손상, 암호, 100MB 초과 → 상태 기록 + 파일명만 색인. **수정 시각이 바뀌면 1회 재시도.**
- 워커가 비정상 종료하면 해당 파일을 실패로 기록하고 워커 재시작.

## 7. 보안 · 개인정보

### 7.1 보호 계층
1. **EFS**: `index\` 폴더 전체. Windows 사용자 계정에 묶인 커널 수준 암호화. 불가(Home 에디션, 정책 차단) 시 **경고 표시 후 계속 사용**.
2. **개인정보 비색인**: 식별번호는 색인 텍스트에서 `⟨주민번호⟩` 등 자리표시자로 치환. 원문 번호는 어떤 색인에도 저장하지 않음.
3. **SQLCipher**: 미리보기용 청크 원문과 메타데이터. 키는 DPAPI(CurrentUser)로 보호.

### 7.2 개인정보 탐지 (1차)
- 대상: 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호, 계좌번호, 휴대폰번호, 이메일.
- 주민·외국인등록번호는 검증 숫자 확인으로 오탐 감소.
- 결과: 문서별 유형별 개수 저장.
- **번호로 검색**: 정규화(하이픈·공백 제거) 후 **HMAC-SHA256(DPAPI 보호 키)** 값만 색인. 검색어가 번호 형식이면 같은 HMAC으로 정확 일치 검색. 부분 번호 검색은 지원하지 않음.
- **이름은 색인함**(이름으로 검색 가능). 이름·주소만 있는 문서는 1차에서 "개인정보 포함"으로 분류되지 않음(로드맵).

### 7.3 표시
- 결과 배지 `🛡 개인정보 포함 · 주민번호 3 · 휴대폰 2`, 필터, 개인정보 점검 화면(UI D5-⑤).
- 미리보기 마스킹: `900101-1******`, `010-****-5678` 등.
- **번호 값은 점검 화면·로그·진단 보고서 어디에도 표시하지 않음.**

### 7.4 네트워크 0 보장
- `cargo-deny`로 HTTP 클라이언트 크레이트(reqwest, hyper, ureq, isahc 등) 의존 금지 → CI에서 차단.
- Tauri CSP `default-src 'self'`, 업데이트 플러그인 미사용.
- 로그에 문서 본문·개인정보 기록 금지.

### 7.5 권한
- 앱·워커: 사용자 권한. 서비스: SYSTEM(파일명 메타데이터만). 파이프 ACL: 대화형 로그온 사용자만.

## 8. 검색 · 순위

### 8.1 검색어 해석
- 날짜 표현("작년", "지난달", "2024년 상반기") → 📅 칩. **필터가 아닌 순위 가산**, 칩 ✕로 해제.
- 번호 형식 → HMAC 정확 일치 경로.
- 약어·동의어 확장: 원래 단어보다 낮은 가중치로 OR. 검색 시점 적용(사전 변경 시 재색인 불필요). 내장 사전(중앙행정기관 약어) + 기관 TSV(가져오기/내보내기).

### 8.2 검색 경로
| 경로 | 방식 | 목표(저사양) |
|---|---|---|
| 파일명 | 서비스(전체 디스크) + 문서 목록 | < 50ms, 입력 즉시 |
| 키워드 | tantivy BM25. 필드 가중치: 공문 제목 > 파일명·문서 제목 > 소제목 > 본문. 본문은 **형태소 필드 + bigram 필드** 이중 색인 | p95 < 150ms |
| 의미 | 검색어 임베딩 → 이진 벡터 SIMD 스캔으로 후보 1,000 → int8 재계산 → 상위 청크 200 | 최종 p95 < 500ms |

### 8.3 결합 · 순위
- 문서 단위 **RRF(k=60)**. 문서 점수 = 최고 청크 점수 + 다수 청크 일치 소폭 가산.
- 보정: 정확 구절 일치 가산, 최근 문서 약한 가산, 날짜 칩 기간 가산.
- 재순위 모델(cross-encoder)은 1차 제외(M0에서 측정만).

### 8.4 버전 묶기 (색인 시 계산)
- 파일명 정규화: `최종`, `최최종`, `수정(본)`, `확정`, `(안)`, `vN`, `(N)`, `- 복사본`, `final`, 날짜(`yyyymmdd`, `yymmdd`) 제거.
- 같은 정규화 이름 **그리고** (같은 폴더 **또는** 문서 벡터 코사인 ≥ 임계값(기본 0.9, 데이터로 조정)) → 같은 묶음.
- 대표는 최신 수정본. 이름만 같고 내용이 다른 파일은 묶지 않음.

### 8.5 필터 · 정렬
- 필터: 형식, 수정일, 공문 시행일, 수신처/발신 기관, 폴더, 🛡 개인정보, 🔒 DRM.
- 정렬: 관련도(기본), 최신순.

### 8.6 단계적 결과 전달
- 파일명(즉시) → 키워드(입력 멈춤 150ms) → 의미(임베딩 완료). 화면 동작은 UI D2를 따른다.

## 10. 모델 관리

- 기본: EmbeddingGemma 2 텍스트 전용 GGUF(Q8 또는 Q4 — M0 결정)를 설치파일에 포함.
- **모델 프로필**(TOML): 이름, 파일 해시, 원본 차원, 저장 차원, 최대 토큰, 검색어/문서 접두어 템플릿, 풀링 방식. 알려진 모델 몇 개는 내장, 미지 모델은 고급 설정에서 수동 입력.
- **모델 지문** = 파일 해시 + 프로필 해시. 벡터 저장소 디렉터리 이름으로 사용 → 서로 다른 모델의 벡터를 섞지 않음.
- 교체 흐름(UI D6): GGUF 선택 → 자동 검사(로드·차원·예문·속도) → 새 벡터 색인을 백그라운드에서 별도 생성(기존 모델로 계속 검색) → 원자적 교체 → 이전 색인 보관/되돌리기/삭제.
- 2차 언어 모델 슬롯: 1차는 비활성 자리만. RAM 용량으로 차단하지 않고 필요 메모리 안내만.
- 기관 정책 파일(MSI 속성으로 지정, 설치 폴더)로 기본 모델·설정 고정 가능. 고정 항목은 UI에 🔒.

## 12. 개발 환경 · 테스트 전략

### 12.1 개발 환경
- macOS에서 `platform`/`svc`를 제외한 전 크레이트 개발·테스트. Windows 전용 코드는 `platform`에 격리(스텁 제공).

### 12.2 3단계 검증
1. **GitHub Actions (windows 러너, 자동)**: 빌드, 단위·통합 테스트(USN·DPAPI·EFS·서비스·MSI 설치/제거), E2E(tauri-driver), `cargo-deny`, 릴리즈 산출물 + SHA-256.
2. **사내 폐쇄망 PC (사용자 수행)**: 마일스톤 단위 릴리즈 반입 → `kra-search.exe --diagnose` 실행 → 보고서 반출.
   - 보고서: 환경(OS 빌드, CPU 명령어, RAM, EFS 가능 여부, WebView2 버전, 단축키 충돌, 감지된 백신), 합성 문서 벤치마크(임베딩 속도, 검색 지연), 실제 문서 추출 통계(형식별 성공/실패/DRM/시간 초과, 오류 유형), 로그.
   - **문서 본문·파일 경로·개인정보 미포함.** 경로는 확장자+해시만. 사람이 읽을 수 있는 JSON/텍스트. 맨 위에 옮겨 적을 수 있는 요약 몇 줄.
3. **폐쇄망 내 품질 평가**: 사용자가 `질의<TAB>정답 파일명` TSV 20~50개 작성 → `--eval queries.tsv` → nDCG@10, Recall@20, 실패 질의 번호만 출력.

### 12.3 테스트 종류
- 단위: 형식별 추출 샘플(배포용·암호·손상 HWP 포함), 개인정보 탐지(합성 번호만), 버전 정규화, 날짜 해석, RRF, 순서 변경 상태 기계.
- 품질 평가 세트(공개): 공개 공공 문서(보도자료, 규정집, 정보공개 원문, 마사회 공개 자료) + 질의 ~100개 + 정답 → nDCG@10, Recall@20. 모델·청크 크기·차원·양자화·bigram 가중치 결정 근거.
- 견고성: `cargo-fuzz`로 HWP/HWPX/PDF 추출기 퍼징. 워커 비정상 종료 시 상주 앱 생존 확인.
- 성능: §13 기준을 벤치마크로 자동 측정(`--diagnose`에 포함).
