# 구현 판단 기록

스펙·계획이 정하지 않은 것을 구현 중에 정한 기록. 제품 설계 결정은 [스펙](../superpowers/specs/2026-10-12-kra-search-design.md)과 [UI 결정](../design/ui-decisions.md)에, M0 수치 기반 잠정 결정(양자화·차원·청크 크기·후보 수)은 [docs/m0/results.md](../m0/results.md)에 있다 — 여기에 되풀이하지 않는다.

형식: **판단 — 이유 — 틀렸을 때의 비용**. 상태: `유효` / `대체됨(→ DEC-xxx)` / `잠정`.
뒤집을 때는 지우지 말고 상태를 바꾸고 새 항목을 추가한다.

(2) **워커 재활용**(M1 최종 리뷰): 지금 워커가 읽은 파일 크기 합이 64MB(`RECYCLE_AFTER_INPUT_BYTES`)를 넘거나, 1,000개(`RECYCLE_AFTER_FILES`)를 처리했거나, 응답 줄이 16MB(`RECYCLE_AFTER_LINE_BYTES`)를 넘으면 정상 워커를 내려놓고 다음 요청 때 새로 띄운다(`recycles`, 비정상 종료 재시작 `restarts` 와 따로 셈). 상주 워커가 큰 입력 파일(그림 많은 HWPX)마다 파일 크기의 약 3배씩 늘고 돌려주지 않아 공개 세트 1,000개에서 490MB 까지 올랐다 — 입력 크기 기준이 주된 장치이고(응답은 수 KB 라 응답 크기 기준으로는 줄지 않음) 고친 뒤 약 180~240MB, 색인 시간 4.8 → 5.0초(프로세스 23개). | 파일마다 프로세스 생성은 비쌈(DEC-025).
